The promise

Every site you visit, stays visitable.

Today's web is rented. The site you bookmarked five years ago is probably a 404 by now. The domain expired, the company pivoted, the host shut down — and your link died with it.

PearBrowser is built on the Pear runtime and the HiveRelay backbone. Sites are Hyperdrives addressed by public key, replicated peer-to-peer, and pinned 24/7 on a relay network you can join too. The publisher's laptop being offline doesn't matter — the relays carry the bytes.

When you bookmark a `hyper://` URL, you bookmark a thing that exists. Not a thing that resolves to a thing if a company decides to keep paying for it.

↑ You publish — block editor, signed seed-request, hyper://key/ in hand.
⟳ 5 relays pin it automatically, in two regions. 365-day TTL.
⏻ You close your laptop. The site stays reachable.
✓ Anyone with the key opens it in PearBrowser — or any web browser via hyper-fetch.
What it is

Three things in one app — each fully P2P.

No "P2P module for an existing Chromium." Built bottom-up on the Holepunch stack: Hyperswarm for discovery, Hyperdrive for storage, Hyperbee for local data, Ed25519 for identity.

🌐

Browse hyper://

Paste a drive key — hex or z-base-32 — and PearBrowser streams the content directly from peers through the Hyperswarm DHT. Multi-tab, back/forward, bookmarks, history. Devtools when you want them.

📦

Run Pear apps

Click a pear:// link, the app opens in its own isolated window. Load any decentralised catalog Hyperdrive — browse, install, launch, uninstall. No store gatekeeper. No 30% cut. Featured: Keet, PearPass, HiveWorm.

✒️

Publish your own

Built-in block editor — headings, paragraphs, images, lists, quotes, code, raw HTML. Publish creates a Hyperdrive, signs an Ed25519 seed-request, broadcasts to HiveRelay, and waits for at least one relay to actually replicate before saying done. Copy the hyper:// URL. Share it. It works.

Quickstart

Up and running in thirty seconds.

PearBrowser is a Pear runtime app. Install the runtime once (it auto-fetches the matching native binary), then run PearBrowser by its public key.

~/pearbrowser — zsh
# 1. Install Pear (one time, all three OSes)
$ npm i -g pear
$ pear # bootstrap

# 2. Launch PearBrowser
$ pear run pear://tco5k7h38uoxatedp1wongdbhjxow1x7jiwm3t1i9cujbebhsbty
  1. Need Node first? Install Node.js 20+. Pear ships through npm.
  2. First-launch onboarding walks you through generating an identity (BIP-39 backed) and picking a first site to visit.
  3. Tabs persist across launches — open today, close, reopen tomorrow, exact same tabs back.
  4. Pear runtime updates itself — when we ship a new PearBrowser release, your next launch hot-syncs the new bytes from the swarm.

Heads-up: pear run is officially deprecated as of Pear runtime v2.4.0. It still works today and will continue to for the foreseeable future. The longer-term distribution path is signed native installers (.app / .exe / .deb) via pear build — coming soon to a release near you. Nothing breaks until then.

FAQ

Honest answers.

How is this different from Beaker Browser?

Beaker pioneered P2P browsing on the original Dat protocol. PearBrowser builds on the current-generation Holepunch / Pear stack — same philosophy, modern transport (UDX + Hyperswarm + DHT-over-WebSocket relays instead of Dat DHT), first-class publishing, and explicit HiveRelay pinning so sites stay up when your laptop doesn't.

What happens to my site when I close my laptop?

Nothing — that's the point. When you publish, the relays accept your signed seed-request, replicate the drive's blocks, and serve them to anyone with the key. The publisher (you) can be offline indefinitely. Re-pin once a year to refresh the TTL.

Who pays for the relays?

The public HiveRelay network is open source (Apache-2.0) and free to use today. It's a small foundation network — soft replication factor of 3, generous quotas. If you want guaranteed 24/7 availability on hardware you control, the repo ships a one-binary relay you can run on any VPS for the cost of a small Hetzner box.

Can I read hyper:// from a regular browser?

Yes, via hyper-fetch — a 5 KB drop-in JS library that talks to the HiveRelay HTTP gateway. Works in every browser, every PWA, every link previewer. The full peer experience (publishing, identity, signed login) still requires PearBrowser.

What if I lose my laptop?

If you backed up your 12-word phrase (Settings → Moving to a new device?), you restore your identity on a new machine and everything still works — bookmarks, profile, login grants for sites that recognise you. If you didn't back up: the drives you published stay alive on the relays forever, but you can never update or unseed them. Write the phrase down.

Is there a mobile version?

Not yet for the full desktop experience. A PWA viewer built on hyper-fetch is in scope — read any hyper:// drive from a phone browser, no install. Native mobile companion with identity sync via shared seed is the next major release.

Is it Apple/Google notarised?

Pear runtime itself is signed (the binary the user installs first). PearBrowser runs inside it as a published app — its security model is the Hypercore signing key, not OS-level codesigning. Per-OS notarised installers are on the roadmap when there's reason to ship them; the cross-platform pear:// path covers most users.

Ready to take your sites off the cloud?

Run PearBrowser today. Open the Sites tab. Publish your first site — pinned to HiveRelay before you hit save, served by five relays in two regions, signed by your identity, addressable by public key.
